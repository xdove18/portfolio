# Handoff: Агентство Pro — CRM для риелторов

## Обзор

CRM для агентства недвижимости. Главная задача продукта: ни один клиент не получает
повторный звонок от второго риелтора, потому что вся история касаний (звонки, показы,
сообщения, встречи) видна всей команде в одной ленте, а карточка чужого клиента
прямо говорит, кто его ведёт и что было последним.

В пакете: рабочий десктоп-прототип со всеми разделами и обучением, три анимации
(таймлапс создания клиента, обзор разделов, мобильные экраны) и анимированная
заставка кейса 457,5 × 210.

## О файлах в пакете

Файлы в `prototypes/` — **дизайн-референсы, сделанные на HTML**. Это прототипы,
показывающие внешний вид и поведение, а не продакшн-код для копирования.
Задача: **воспроизвести эти экраны в существующем окружении кодовой базы**
(React, Vue, Svelte, native — что уже используется), опираясь на её паттерны и
библиотеки. Если окружения ещё нет, выбрать подходящий фреймворк и реализовать там.

Файлы `.dc.html` открываются прямо в браузере (нужен лежащий рядом `support.js`).
`.jsx` — анимационные сцены, они подключаются из соответствующих `.dc.html`.

## Точность

**High-fidelity.** Цвета, типографика, отступы, радиусы и состояния финальные —
воспроизводить пиксель в пиксель, подставляя компоненты своей системы.
Исключение: анимации — это раскадровки того, как ведёт себя интерфейс, а не
требования к реализации motion-слоя.

### 1а. Экран столкновения — чужой клиент

Главный экран кейса. Риелтор открывает клиента, которого ведёт коллега.
Сигнал «клиент занят» должен быть сильнее призыва позвонить.

- Над шапкой карточки — плашка: фон `color-mix(in srgb, phone 14%, panel)`
  (спокойный голубой), радиус 14, padding 12 / 16; квадрат 32 с инициалами коллеги
  на `color-mix(phone 30%, panel)`; заголовок 13 / 600
  «Ведёт Марина Грязнова · последнее касание вчера в 17:40 · показ на Толстого д.25»,
  под ним 12px `tx2`: «Клиент в работе у коллеги. Прежде чем звонить, уточните у неё».
- Кнопки меняются местами: главная (`cta`) — «Написать Марине», «Позвонить» —
  вторичная (`bg2`).
- Звонок не блокируется: решение остаётся за риелтором, интерфейс только
  расставляет приоритет.
- Свой клиент плашки не получает.

### 2. История взаимодействий

Группировка по дням: слева колонка 96px с днём (13 / 600) и датой (моно 11px `tx3`),
справа лента, отделённая вертикальной линией `hair`, на линии — точка 7 × 7 цвета типа
касания напротив каждого события.

Событие — плашка `bg2`, радиус 14, padding 12 / 14: иконка типа 16px цветом типа,
заголовок 14 / 600, мета (время моно 11px, автор 12px) и, если заметки есть, метка
с иконкой закладки и счётчиком: «1 заметка» / «2 заметки».

Заметки внутри события (отступ слева 36):
- аватар-квадрат 20 × 20, радиус 6, фон `bg3`, инициалы моно 9px;
- имя автора 13 / 600, время моно 11px `tx3`;
- текст 13px, `line-height: 1.6`;
- действия «Изменить» и «Удалить» — 12px `tx3`;
- в конце ветки — «+ Добавить заметку» 12 / 600 цветом `cta`.

Если заметок нет, у события показывается только «+ Добавить заметку» — событие с
заметкой и событие без заметки должны читаться по-разному с одного взгляда.

### 3. Показы, Сделки, Дашборд, Отчёты, Команда

Разделы спроектированы под ежедневную работу риелтора: что сделать сейчас,
что просрочено, где свободное время.

- **Показы** — расписание на день: переключатель «Сегодня / Завтра / Неделя»,
  сводка «4 показа · 1 без итога · 2 впереди · 3 ч 15 мин в разъездах», плашка
  «Показы без итога» с кнопкой внести итог. Строки `58px 3px 1fr 150px 120px 118px`:
  время + длительность (моно), полоска цвета итога, объект (адрес, цена, комнаты,
  заметка с показа), клиент + риелтор, итог, действия (позвонить, заметка,
  «Итог» / «Статус»). Между показами — строка окна «Окно 2 ч 30 мин · + Вписать».
- **Сделки** — список, а не канбан: клиент + сумма + объект, этап точкой, ближайший
  шаг, документы (счётчик «4 / 5», полоса, чего не хватает), срок (просрочено —
  `stR`, скоро — `stW`), действия. В шапке: в работе, сумма, просрочены, ждут документы.
- **Дашборд** — метрики с дельтой, воронка по клиентам (Новые лиды → Закрыто,
  полосы `cta`, этапы, где клиенты стоят > 7 дней, — `stW` с подписью «застряли»),
  график касаний по дням и блок, зависящий от роли (см. «Роли»).
- **Отчёты** — четыре карточки `panel` с названием, периодом (моно `tx3`), описанием
  и кнопками «Скачать» (`cta`) и «Ссылка» (`bg3`).
- **Команда** — только руководителю. Строки `1fr 110px 110px 200px`: человек
  с аватаром и ролью, число клиентов, число показов, полоса нагрузки
  (`cta`; при нагрузке > 85% — `msg`).

### 4. Обучение

Обучение работает **точечными подсказками по ходу действия**, а не одним большим
модальным окном. Шаги:

1. «Начните с клиента» — подсвечена первая строка списка;
2. «Это клиент коллеги» — подсвечены плашка и кнопки «Написать Марине / Позвонить»;
3. «Запишите касание» — подсвечена кнопка «+ Добавить событие»; текст: сначала
   заметка, статус меняйте, только если он правда изменился;
4. «Кто остыл» — подсвечена иконка фильтров в шапке.

Подсветка: рамка 2px цвета `cta` вокруг реального элемента с отступом 7px и
затемнением остального экрана через `box-shadow: 0 0 0 9999px rgba(6,6,5,.66)`.
Рамка должна считаться от фактических координат элемента (в React — `ref` +
`getBoundingClientRect`), а не задаваться константами, иначе она «съезжает» при
изменении вёрстки.

Подсказка рядом с элементом: карточка 274px, `panel`, радиус 14, тень
`0 22px 54px rgba(0,0,0,.6)`; внутри — счётчик «2 / 4» моно 10px цветом `cta`,
крестик, заголовок 14 / 600, текст 12px `tx2`, точки-прогресс (активная — пилюля
22 × 7 цветом `cta`) и кнопки «Назад» (`bg2`) / «Далее» (`cta`) высотой 28.

### 5. Добавление события (форма внутри карточки)

Форма раскрывается внизу карточки клиента вместо кнопки «+ Добавить событие»,
без модального окна и затемнения: история остаётся видна. Блок `bg2`, радиус 16,
padding 16; поля — фон `panel`, без обводок.

Порядок полей — по ценности записи:
1. **Заметка — первая.** Для показа обязательна: заголовок «Как прошёл показ *»
   и подпись «обязательно — по ней коллеги поймут, что предлагать дальше»;
   без текста «Сохранить» не срабатывает, поле подсвечивается. Для звонка,
   сообщения, встречи — «по желанию».
2. Тип события чипами (Показ квартиры, Звонок, WhatsApp сообщение, Встреча в офисе,
   Email, Другое). Выбранный — фон `cta`, текст `pillTx`.
3. Контекстное поле: адрес объекта (с быстрыми чипами недавних адресов) для показа,
   длительность для звонка. Дата редактируемая, по умолчанию «сейчас».
4. **Статус — необязателен.** По умолчанию ничего не выбрано, подпись
   «Статус сейчас «Активен» — меняйте, только если что-то изменилось». Повторный
   клик снимает выбор. Выбранный чип — фон `color-mix(in srgb, <цвет статуса> 22%, panel)`.

Если статус изменён: в событие добавляется строка «Статус: Активен → Жду звонка»,
в шапке карточки обновляется «кто и когда поставил», владелец клиента (если это
не автор записи) получает уведомление. Так статус перестаёт молча перезаписываться
последним, кто нажал кнопку.

Внизу «Сохранить» (`cta`) и «Отменить» (`panel`), высота 36, радиус 999.

### 6. Мобильная версия (390 × 844)

Та же палитра и та же плотность, что на десктопе.

- Статус-бар 48, шапка 56: слева бургер или «назад», по центру заголовок, справа
  фильтры или «ещё». Все зоны нажатия ≥ 44px.
- Список клиентов: два сводных чипа, поиск (44 / 999), чипы статусов, карточки
  клиентов `panel` (выбранная — `bg3`) с аватаром, статусом, суммой и спарклайном.
- Навигация между разделами — **через шторку меню снизу**: бургер → шторка
  (радиус 24 сверху, «ручка» 36 × 4, заголовок, шесть пунктов по 48) → выбор пункта.
- Фильтры — такая же шторка: группы «Статус» и «Срок контакта» с чекбоксами 18 × 18
  (отмеченный — заливка `cta`), внизу «Применить» и «Сбросить».
- Карточка клиента: у чужого клиента сверху та же голубая плашка «Ведёт Марина
  Грязнова · последнее касание…», аватар 64, имя 20 / 600, статус с автором,
  строка фактов (бюджет, комнаты, районы), две кнопки в ряд («Написать Марине» /
  «Позвонить» для чужого клиента), история с заметками, закреплённая внизу кнопка
  «+ Добавить событие».
- Форма события: строка «клиент + дата», **заметка первой** (обязательна для показа),
  чипы типа, поле адреса, необязательные чипы статуса с подсказкой о текущем
  статусе и закреплённый футер с двумя кнопками; тело формы скроллится.
- Показы — карточки расписания с окнами «+ Вписать», Сделки — карточки со сроком,
  ближайшим шагом и документами, Дашборд — с воронкой.
- В меню риелтора 5 пунктов (без «Команды»).
- Переходы: вглубь (карточка, форма) — сдвиг слева направо с тенью, как push-навигация;
  между разделами — мягкое появление сверху вниз, без одновременного показа двух экранов.

### 7. Заставка кейса (457,5 × 210)

циклом 7 секунд. Реализовано на CSS-анимациях, без JS.

## Взаимодействия и поведение

- Клик по пункту меню переключает раздел; активный пункт подсвечивается.
- Клик по строке клиента открывает его карточку справа (на мобилке — отдельный экран).
- Поиск фильтрует список по имени и телефону; при пустом результате — «Клиентов не найдено».
- Фильтры: статус клиента и срок последнего контакта (в том числе «не было касаний 7 дней»).
- «+ Добавить событие» раскрывает форму внизу карточки; после сохранения событие
  появляется в истории, счётчики пересчитываются; статус меняется, только если его
  выбрали явно (с записью в ленте и уведомлением владельцу).
- В карточке чужого клиента «Написать Марине» открывает чат с коллегой,
  «Позвонить» остаётся доступным.
- Заметки: добавление, редактирование и удаление внутри события; у события может быть
  несколько заметок от разных риелторов.
- Обучение запускается иконкой «?» в шапке, шаги переключаются
  «Далее / Назад», закрывается крестиком.
- Анимации появления: карточки и строки поднимаются на 26px с `opacity 0 → 1`,
  `ease-out-cubic`, длительность ~550ms, задержка между соседними элементами 70–120ms.

## Состояние

- `page` — активный раздел.
- `currentUser { id, role: 'realtor' | 'manager' }`.
- `clients[]` с `ownerId`, `status`, `statusSetBy`, `statusSetAt`; `selectedClientId`, `query`, `filters { statuses[], lastContact }`.
- Флаг столкновения: `client.ownerId !== currentUser.id` → плашка и смена приоритета кнопок.
- `events[]` у клиента: `{ id, kind, title, datetime, authorId, notes[] }`.
- `notes[]` внутри события: `{ id, authorId, datetime, text }`.
- `eventForm { open, kind, note, addr, date, status | null, noteError }`.
- `tour { open, step }`.
- `theme` — light / dark.
- Мобильная версия дополнительно: `sheet` (`none | menu | filters`), стек навигации.

## Ассеты

Все иконки — инлайновые SVG 24 × 24, `stroke: currentColor`, `stroke-width: 1.7–1.8`,
скруглённые концы: дом (показ), телефон (звонок), облако сообщения, календарь (встреча),
лупа, фильтр, колокольчик, закладка (заметка), стрелка «назад», бургер, «ещё».
Растровых изображений и сторонних иконочных наборов нет. Шрифты — Google Fonts:
Inter и JetBrains Mono.
